# [CHK-Verificacion_Pruebas] Checklist de Calidad — Verificación de Pruebas

## Metadatos de la Revisión
| Campo | Valor |
|---|---|
| Proyecto | Sistema bajo prueba |
| Entrega / Cambio revisado | |
| Fuente de solicitud | Reunión inicial / WhatsApp / Cliente / Interna |
| Responsable de pruebas | Analista de Verificación y Pruebas |
| Fecha de revisión | |
| Resultado general | Aprobado / Rechazado |

---

## Instrucciones
Marcar cada ítem como:
- Cumple
- No cumple
- N/A No aplica al proyecto

Una prueba no debe cerrarse como aprobada si existe un ítem obligatorio marcado como No cumple.

---

## 1. Planeación de la Prueba

| ID | Criterio | Estado | Observación |
|---|---|---|---|
| PP-01 | Existe un plan de pruebas ligero para la entrega o cambio visible al Cliente. | | |
| PP-02 | El plan indica qué se va a probar y qué no se va a probar. | | |
| PP-03 | La fuente de solicitud está identificada: reunión inicial, WhatsApp, Cliente o interna. | | |
| PP-04 | Si el cambio está fuera del alcance inicial, está marcado explícitamente. | | |

---

## 2. Caso de Prueba

| ID | Criterio | Estado | Observación |
|---|---|---|---|
| CP-01 | El caso de prueba tiene ID, nombre y requisito o cambio relacionado. | | |
| CP-02 | El caso incluye pasos claros y resultado esperado. | | |
| CP-03 | El caso indica datos de prueba o condiciones necesarias para ejecutarlo. | | |
| CP-04 | El caso indica si requiere visto bueno del Cliente. | | |

---

## 3. Ejecución y Evidencia

| ID | Criterio | Estado | Observación |
|---|---|---|---|
| EE-01 | La prueba fue ejecutada en ambiente local o ambiente definido. | | |
| EE-02 | El resultado real quedó registrado como aprobado, fallido o bloqueado. | | |
| EE-03 | Existe evidencia mínima: captura, log o nota clara. | | |
| EE-04 | Si la prueba falló, se registró defecto o ajuste asociado. | | |

---

## 4. Cierre y Validación

| ID | Criterio | Estado | Observación |
|---|---|---|---|
| CV-01 | Los defectos o ajustes tienen responsable y estado. | | |
| CV-02 | Si aplica, el visto bueno del Cliente quedó registrado. | | |
| CV-03 | El registro de ejecución permite entender qué se probó y qué pasó. | | |
